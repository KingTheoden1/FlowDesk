FD-040 · Alpha CRM
Implement JWT refresh token rotation
In Progress High Priority Due Apr 22, 2026
Implement a secure JWT refresh token rotation scheme. When a refresh token is used, it should be invalidated and a new one issued atomically. Expired or revoked refresh tokens must return 401. Store refresh tokens in the database with a hash and expiry timestamp.

Acceptance criteria: refresh endpoint returns a new access + refresh token pair, old token is invalidated after use, concurrent refresh attempts are handled gracefully without race conditions, and all token operations are covered by unit tests.

I've started the implementation. Planning to use a sliding window approach — each refresh generates a new token and invalidates the old one. Will use a DB table with hash + expiry. Should be done by tomorrow EOD.
